# Project Context

Architectural law for this repository. `AGENTS.md` (working rules for every AI agent) and
`CLAUDE.md` (Claude Code specifics) build on it. The design rationale behind most of what
follows is written out in `README.md`; read the matching README section before changing a
behaviour it explains.

## 1. Overview

**nemaleba.rs** shows planned and emergency electricity and water outages in Serbia, by
city, municipality and street, in Serbian Latin, Serbian Cyrillic and English.

It is a static site. A TypeScript pipeline reads what public utilities publish (ЕПС
Дистрибуција for electricity across the country, a growing list of municipal water
utilities), matches the place names against the state Address Register (RGZ), and writes
JSON into `static/data/`. GitHub Actions runs it 13 times a day, builds the SvelteKit site,
deploys it to GitHub Pages, sends web-push notifications and commits the refreshed dataset
back to `main`. A Cloudflare Worker with D1 holds push subscriptions and anonymous comments,
and also triggers the refresh workflow, because GitHub's own cron drops runs.

The repository is **public** and licensed AGPL-3.0-or-later. Everything tracked is public.

## 2. Stack

- **Site:** SvelteKit 2 + Svelte 5 (runes, `*.svelte.ts` stores), `@sveltejs/adapter-static`,
  Vite 8 (Rolldown), TypeScript 6, `@lucide/svelte`, `@floating-ui/dom`.
- **Pipeline:** TypeScript run with `tsx` (`scripts/`), no framework.
- **Tests:** Vitest 3 (`npm test`), `svelte-check` (`npm run check`).
- **Push and comments:** Cloudflare Worker (`worker/`), D1 database `nemaleba-subscriptions`,
  `web-push` with VAPID keys.
- **CI/CD:** `.github/workflows/refresh.yml`: jobs `build` → `deploy` → `notify`, plus `ledger`.
- **Node:** CI builds the site on Node 20. Wrangler needs Node 22+, so switch only for
  `worker/` commands.

## 3. Architecture and layout

```
scripts/                 data pipeline, run by Actions (npm run data)
  pipeline.ts            entry: SOURCES list, collect, source-health check, emit
  sources/               one OutageSource per utility (HTTP fetch), httpClient, sourceLog
  parsing/               HTML / announcement / prose parsers + parsers.test.ts (fixtures)
  registry/              city registry, RGZ place matching, roll-up, source health, history
  emit/                  dataset writer, street index, sitemap/site index
  notify.ts, notify/     push sending, subscriber directory, delivery log
  ci/                    ledger merge/adopt, freshness and deployment waits, persist-dataset
  dev/                   fixture capture, RGZ import
src/lib/
  domain/                types and static directories, no I/O (outage, city, provider, utility, waterUtilities)
  data/                  outageRepository: fetches static/data JSON on the client
  address/ text/ time/   address folding, Cyrillic ↔ Latin, Serbian calendar and time windows
  search/                city and street search (sharded street index)
  i18n/                  locale routing, messages, provider names
  notifications/         push client, preferences, install prompt, notification log
  components/            UI components
src/routes/              [[locale]]/ home, [city], [city]/komentari, [city]/ulica/[street], obavestenja
worker/                  Cloudflare Worker: push subscriptions, comments, cron → workflow dispatch
data/rgz/                Address Register derivative (names and ids, no geometry), committed
data/fixtures/           one captured response per source, for parser tests
static/data/             GENERATED by the pipeline and committed by the bot
```

Data flow: `sources/*` fetch → `parsing/*` turn announcements into `RawOutage`s →
`registry/*` match places against RGZ and roll municipalities up to cities → `emit/*` write
`static/data/{registry,sources,coverage,unknown-places,notified}.json`, `cities/*.json` and
`streets/*` → the site prerenders city pages from `registry.json` and loads the rest on
the client.

## 4. Contracts (strict)

- **Silence is the failure mode.** The worst thing this site can do is show nothing when
  something is wrong, because readers take an empty page as "my power and water are on".
  Never present unread, unparsed or unmatched data as "no outages". Where precision cannot
  be had, the page says so in words. A parser that guesses or a match that is "probably
  right" is not acceptable.
- **A utility is one `OutageSource`.** Adding a utility means one file in `scripts/sources/`,
  a parser if needed, a `SOURCES` entry in `scripts/pipeline.ts` and a fixture. Nothing else
  changes. Procedure: `docs/AI/skills/add-water-source.md`.
- **Host failure versus parser failure.** A host that will not answer raises
  `SourceUnreachable` and is recorded as `unreadable` in `sources.json`; the run goes on. A
  parser that throws is a bug and fails the run. Do not blur these two.
- **Source-health regression check.** A source that produced rows before and reads cleanly
  but yields none stops the publish. Do not weaken this check. `ALLOW_EMPTY_SOURCES=1` is only
  for silence confirmed to be genuine.
- **No parser change without a fixture.** Every parser has a captured fixture in
  `data/fixtures/`, captured under the user agent the source really needs, and a case in
  `scripts/parsing/parsers.test.ts`. Source health counts rows and cannot see a wrong row.
- **Attribution.** Every outage row carries its `sourceUrl`. Contacts come from the source's
  `Provider` (`coverage` = national or city ids). `src/lib/domain/waterUtilities.ts` is a
  contacts-only directory for municipalities that no scraped source covers. Never list a
  city in both places.
- **The bot owns generated data.** `static/data/**` is written by the pipeline and committed
  hourly by `nemaleba-bot`. Do not hand-edit it, and do not include a local `npm run data`
  output in a code change. `registry.json` accumulates municipalities and never shrinks.
- **Notifications are sent exactly once.** Only the scheduled run sends. Runs are serialised
  (`concurrency: refresh`). The `notified.json` ledger is merged as a union, never
  overwritten. An outage is recorded only after delivery reached a subscriber, or no
  subscriber wanted it. Read README "Sending exactly once" before touching `notify`,
  `scripts/ci/*` or the workflow.
- **Never regenerate VAPID keys.** Every existing subscription is encrypted against the
  current public key.
- **Prerender what strangers arrive at.** City and comments pages are prerendered in all three
  locales, because link previews in WhatsApp, Viber and Facebook do not run JavaScript.
  Street pages are not prerendered and run behind the SPA fallback. Data inlined into
  `+layout` reaches every prerendered page, so keep static directories out of it.
- **The locale lives in the URL.** Latin is bare, Cyrillic is `/sr-cyr` and English is
  `/en`. Build links with `src/lib/i18n/routing.ts`, never by concatenating strings.
- **Both scripts.** Slugs and search fold Cyrillic and Latin onto the same letters
  (`src/lib/text/serbianScript.ts`). Every user-facing string in `src/lib/i18n/messages.ts`
  has `sr`, written in Cyrillic, and `en`. Latin is derived with `toLatin`, so never write a
  separate Latin copy.
- **Privacy.** Preferences live in `localStorage` only: no cookies, no analytics. Comments
  store hashes, never a raw address. Do not add tracking.
- **Worker migrations.** Each schema change is a new `worker/migrations/vX.Y.Z__what.sql`.
  `v1.0.0__init.sql` is never edited. No CI job applies migrations or deploys the Worker.
- **Measure claims.** A number in README, a comment or a commit message is measured from the
  committed dataset or fixtures, never estimated.

## 5. Conventions

- Comments explain **why**, often by naming the incident that made a rule necessary (see
  `scripts/pipeline.ts`). Keep that voice. Do not add comments that restate the code.
- Commit messages have an imperative subject in plain words, with no `feat:`/`fix:` prefix
  ("Tell an unreachable host from a broken parser"). The body is prose: what broke, what it
  looked like to a reader, and why this change is the right answer.
- README is the knowledge base. A design decision with its rationale goes into the matching
  README section. Contributor procedure goes into `CONTRIBUTING.md`.

## 6. Known technical debt and open issues

Recheck each item against current code before relying on it.

- **Sources intermittently unreadable (seen 2026-11-26/27).** In some runs about ten
  WordPress water sources answer at once with non-JSON (`response was not JSON`), most likely
  bot or WAF challenges against GitHub Actions IPs. Gornji Milanovac and Čačak have shown 0 for
  longer.
- **Unreadable is invisible on the site.** `src/` does not read `sources.json`. When a source
  is unreadable, its city JSON is emptied (for example `nis.json` lost about 720 lines in
  1231cb1b), and readers see an empty page with no notice. This is the §4 failure mode.
- `+layout.ts` awaits `registry.json` before anything can paint, which slows every cold load.
  README names deferring it as the first performance fix.
- Street pages render correctly but answer HTTP 404, because GitHub Pages has no redirects
  file.
- Two Node versions are in play: 20 for the site, 22+ for Wrangler.
- README ("Bor … `BROWSER_USER_AGENT`") and `CONTRIBUTING.md` step 4 ("four of them answer
  the collector's own agent with an error") are stale. Every source now fetches with one
  browser user agent (`scripts/sources/httpClient.ts`).
